# חיבורים חיצוניים — מה מקסימום ההרשאות שאפשר לתת לעוזר

נכתב 2026-09-08, בעקבות בקשה לחבר את העוזר ל-Microsoft To Do ול-Connecteam
ולבדוק בשתיהן מה ההרשאות המקסימליות שאפשר לתת לו.

מקור המידע: תיעוד היצרנים דרך חיפוש. `learn.microsoft.com` ו-
`developer.connecteam.com` חסומים לגישה ישירה מסביבת הפיתוח הזאת, ולכן הפרטים
כאן מבוססים על סיכומי חיפוש ולא על קריאה ישירה של הדף. כל מה שנוגע ל-Graph
נבדק מול ה-API האמיתי ברגע שיהיו הרשאות; מה שנוגע ל-Connecteam לא ייבדק בלי
מפתח.

---

## Microsoft To Do — נבנה

**מקסימום ההרשאות: ארבע, וזה הכל.**

| הרשאה | סוג | מה היא נותנת |
|---|---|---|
| `Tasks.ReadWrite` | Delegated | הרשימות והמשימות שלו — קריאה וכתיבה. מכילה את `Tasks.Read`. |
| `Tasks.ReadWrite.Shared` | Delegated | רשימות שאנשים אחרים שיתפו איתו. בלעדיה הן פשוט לא נראות. |
| `User.Read` | Delegated | `/me` — כדי שהעוזר יוכל להגיד לאיזה חשבון הוא מחובר. |
| `offline_access` | Delegated | ה-refresh token. בלעדיה החיבור חי שעה ומת. |

הרשימה הזאת היא `microsoft_scopes.SCOPES`, ואותו אובייקט משמש גם את סקריפט
האישור וגם את הרענון — כדי שהם לא יוכלו להיפרד.

**אין מסלול הרשאות אפליקציה.** משפחת `Tasks.*` ב-Microsoft Graph היא
delegated בלבד: אין service account, אין daemon, ואין דרך לעקוף אישור אנושי
בדפדפן. העוזר פועל בשם איתי, בדיוק כמו מול Google.

**מה שנבנה כאן:** `msgraph.py` (טוקן ובקשות), `todo_tools.py` (רשימות
ומשימות — יצירה, קריאה, עדכון, סימון כבוצע, החזרה, מחיקה, תת-משימות),
`scripts/authorize_microsoft.py` (האישור החד-פעמי), וטבלת `oauth_tokens`
ב-`storage.py`.

**הדבר האחד שחשוב להבין בטוקן.** מיקרוסופט מסובבת את ה-refresh token: כל
פדיון מחזיר טוקן חדש עם 90 יום חדשים, והישן בדרך החוצה. משתנה סביבה לכן לא
יכול להחזיק את הטוקן החי — הוא רק זרע. הטוקן החי יושב בטבלת `oauth_tokens`,
ובשום מצב לא בטבלת `memory`, שנשפכת לתוך ה-system prompt של המודל בכל הודעה.

**שתי תקלות שנראות כמו באג בקוד ואינן:**

- `AADSTS65001` / "need admin approval" — חשבון עבודה שהארגון שלו חסם אישור
  משתמש. `Tasks.ReadWrite` בדרך כלל ניתנת לאישור עצמי, אבל ארגון יכול לכבות
  את זה. בחשבון Microsoft פרטי אין מתג כזה.
- `AADSTS7000215` — הודבק ה-Secret ID במקום ה-Value. Entra מציגה את ה-Value
  פעם אחת. סודות גם פגים — 24 חודשים לכל היותר — והפקיעה שקטה עד שרענון נכשל.

## Connecteam — נחקר, לא נבנה

**התשובה על "מה מקסימום ההרשאות" היא גם התשובה היחידה: הכל.** ל-Connecteam
אין scoping למפתחות API. מפתח אחד = גישה מלאה לכל חשבון החברה, כל העובדים.
מפתח לקריאה בלבד הוא בקשת פיצ'ר פתוחה, לא פיצ'ר.

שלושה חסמים, וכולם אצל המעסיק ולא אצלנו:

1. **גישת API דורשת מנוי Expert ומעלה.**
2. **רק בעל החשבון (account owner) יכול ליצור מפתח** — Settings → API Keys.
   חשבון ה-Connecteam שייך למעסיק, לא לאיתי.
3. **המפתח לא ניתן לצמצום** — ולכן מפתח כזה על בוט וואטסאפ אישי הוא סיכון
   אמיתי שצריך להיאמר בקול, לא רק אי-נוחות.

מה זה היה קונה: `POST /time-clock/v1/time-clocks/{timeClockId}/clock-in` עם
`userId` — כלומר העוזר היה מחתים נוכחות בפועל, לא רק מזכיר. זה שדרוג ממשי
לתזכורת 08:55/17:55, שהיא המשימה הכי מתועדפת בפרויקט.

**מה לשאול את בעל חשבון ה-Connecteam בחברה:** באיזה מנוי הם נמצאים, ואם יש
להם גישה למסלול ה-OAuth 2.0 של Connecteam — שם, בניגוד למפתחות, יש scopes
וטוקנים קצרי-חיים, וזה המסלול היחיד שבו בקשה כזאת סבירה לאשר.

עד שתתקבל תשובה, תזכורת הנוכחות ממשיכה לעבוד בדיוק כמו היום: הודעה בוואטסאפ,
והחתמה ידנית.
